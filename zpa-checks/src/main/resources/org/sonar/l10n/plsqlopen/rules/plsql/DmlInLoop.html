Executing an INSERT, UPDATE, DELETE or MERGE statement once per loop iteration is much slower than performing the same work in bulk, because each iteration pays the cost of a separate context switch between the PL/SQL and SQL engines.

begin
  for rec in (select id from source_table) loop
    update target_table set processed = 1 where id = rec.id; -- Noncompliant
  end loop;
end;

Replace the loop and the row-by-row DML with a single FORALL statement over a collection:

begin
  forall rec in indices of id_table
    update target_table set processed = 1 where id = id_table(rec);
end;

This rule looks through IF/CASE branches and nested BEGIN...END blocks to find DML statements executed directly in the loop body. A DML statement inside a nested loop or inside a FORALL statement is not reported here, since that nested construct is its own scope and is checked independently. Dynamic SQL executed via EXECUTE IMMEDIATE is not reported either.
